# Programme documents

How Project Honeycomb is planned and run. Read them in this order:

1. [ARCHITECTURE-REVIEW.md](ARCHITECTURE-REVIEW.md): what we checked, what we keep and what we propose to change, with links to the decision records in [../adr/](../adr/README.md).
2. [PROGRAM-PLAN.md](PROGRAM-PLAN.md): mission, workstreams, stages and gates, measures, resources and kill criteria.
3. [DEFENCE-MODEL.md](DEFENCE-MODEL.md): how agents get in and stay, the response ladder, and how the IT team is told.
4. [TEAM-AND-AGENTS.md](TEAM-AND-AGENTS.md): human roles, build-agent roles and rules, and the runtime agent rollout.
5. [BACKLOG.md](BACKLOG.md): items with owners, sizes and acceptance criteria for M0 to M5.
6. [MARKET-AND-GAPS.md](MARKET-AND-GAPS.md): comparable products, where they fall short and where we differ.
7. [THREAT-WATCH.md](THREAT-WATCH.md): how we keep watching for new attacks, bugs and market moves.
8. [RISK-REGISTER.md](RISK-REGISTER.md): risks, scores and owners.
9. [M2-PLAN.md](M2-PLAN.md): the plan we followed for M2 (decoys, honeytokens, first incident).
10. [DIRECTION-CHECK.md](DIRECTION-CHECK.md): where we stand against what we promised, after M2.
11. [M3-PLAN.md](M3-PLAN.md): the plan for run identity, egress and the Docker lab, waiting for approval.

The product specification stays in [../PHASE0-SPEC.md](../PHASE0-SPEC.md).
